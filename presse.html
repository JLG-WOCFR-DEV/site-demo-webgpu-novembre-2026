WebGPU-demo-UBS · Presse

Presse

Un « Webflow » WebGPU, sous forme de bibliothèque : on écrit une page HTML ordinaire, quelques attributs disent au GPU ce qu'il doit en faire, et une ligne de script lance le moteur. Cette page est faite ainsi, et rien d'autre.

Démarrer

Une balise script, et des options lues sur la balise html. C'est tout le JavaScript qu'il faut écrire.

<html data-presse-transition="buvard" data-presse-effects="loupe bloom grain">
  …
  <h1 data-gl-text data-gl-morph>Titre</h1>
  <img data-gl-img data-gl-material="lentille" src="…" alt="…">
  <section data-gl-print>…</section>
  <script type="module" src="/src/presse/auto.ts"></script>  <!-- projet Vite -->
</html>

Les images

data-gl-img fait d'une image un plan GPU, aux coins calculés pixel par pixel. Une matière s'y pose par attribut : ici lentille, une loupe qui suit le pointeur avec retard.

Les matières

data-gl-material="poussiere" : l'image se défait en carrés qui montent, puis se recompose. Les autres matières : flammes, nuages, toile, gouttes, givre, trame, filtre, dechirure.

Sur du texte vivant

Une matière se pose aussi sur un bloc de texte. Le givre fond sous le pointeur, puis regèle ; le texte reste sélectionnable, lisible par les lecteurs d'écran, trouvable par la recherche dans la page.

Vitre gelée

Gardez le pointeur dessus : la glace fond, avec un bord d'eau.

Survols et révélations

Deux attributs sur une image GPU. data-gl-reveal la fait apparaître quand elle entre dans l'écran ; data-gl-hover la fait répondre au pointeur. Le plan, ses coins et son ombre ne bougent pas : seule la lecture de la photo change. 

<img data-gl-img data-gl-reveal="rideau" data-gl-hover="deplacement" src="…" alt="…">
<!-- révélation : rideau, dissolution, pixels, tri · survol : deplacement, rvb, onde, pixels -->

La typographie cinétique

Le texte reste du texte HTML, sélectionnable et lu par les lecteurs d'écran ; le GPU en joue la graisse, la largeur et la place. La graisse se règle sur le seuil du champ de distance de chaque lettre : rien à recharger, rien à recalculer. Passez le pointeur, faites défiler.

La direction artistique

Un attribut sur la balise html, et toute la page change de pellicule : texte, images, canvas de tous les composants. Un étalonnage en fin de chaîne (courbes par couche, saturation), un grain animé qui casse aussi les bandes des dégradés, une vignette. Essayez : 

<html data-presse-look="argentique">          <!-- neutre, papier, argentique, nuit, presse -->
<html data-presse-grain="0.06" data-presse-vignette="0.3">   <!-- réglages fins -->

Le défilement

La molette glisse au lieu de sauter, et le défilement reste natif : ancres, clavier, tactile, recherche dans la page. Chaque élément marqué data-scroll reçoit sa progression en variable CSS ; un plan GPU suit son rectangle, donc une transformation CSS le transforme aussi. 

<html data-presse-scroll="doux">
<section data-scroll="pin">            <!-- --p : 0 → 1 pendant la traversée -->
  <div>                                 <!-- épinglé (sticky) -->
    <img data-gl-img style="scale: calc(.55 + .45 * var(--p))" …>
  </div>
</section>

Une section épinglée, une photo qui grandit.

Les composants

Une balise, et c'est posé. <x-liquide>, <x-grille> et <x-lettres> sont déroulées en HTML statique à la construction : la page arrive complète, lisible sans JavaScript, avec sa feuille de style dans l'en-tête. Le comportement n'est chargé que si la page contient le composant.

Entre deux pages, la photo passe : cliquez la légende d'une carte, ou « Sur le mur entier » sur la page d'une photo de la grille. Ce sont de vraies pages, chargées par le navigateur ; seule l'image voyage, d'un rectangle à l'autre, et revient au retour arrière. 

<x-liquide filters="eau:L'eau|terre:La terre" link="grille.html?photo={id}">
  <img src="pont.jpg" alt="…" data-cat="eau" data-id="pont" data-caption="Le pont">
  …
</x-liquide>

<x-grille param="vue" page="grille.html">
  <img src="lac.jpg" alt="…" data-title="Le lac" data-body="…">
</x-grille>

Objet

Un modèle GLB, un SVG ou une image posés dans un studio et rendus en ASCII, tramé, à l'encre, en verre, en particules ou en liquide. Glissez pour le tourner ; déposez votre fichier dessus. Tous les rendus sont sur la page Atelier.

Sommaire en lettres

Sans une ligne de JavaScript : les lettres sont découpées à la construction, le reste est du CSS.

Comment ça marche

  1. Le DOM fait foi. Le navigateur met en page ; le moteur relit les boîtes à chaque image et repeint tout dans un seul canvas.
  2. Chaque lettre est mesurée sur le DOM, caractère par caractère, avec un Range : le texte du GPU tombe au pixel près sur le texte HTML, quelle que soit la fonte, l'approche ou la hauteur de ligne.
  3. Deux atlas de distances, préparés à la construction. Les titres : un atlas MTSDF (angles vifs à toute taille), pour chaque fonte de titre relevée sur les pages. Le texte courant : un atlas SDF dessiné par le même code que dans le navigateur, puis rangé et chargé d'un bloc. Toutes les lettres sont des instances : un seul appel de dessin.
  4. Les images sont des plans qui suivent leur élément, sans buffer de géométrie : quatre sommets générés dans le shader.
  5. Une chaîne après la scène : bloom, repérage, trame, matières, transitions et grain dans une seule passe de composition.
  6. Le morphing apparie les lettres de l'ancien et du nouveau texte : celles qui existent dans les deux voyagent, les autres naissent ou s'effacent.
  7. Sans WebGPU, rien ne casse : la page reste son HTML. Le contenu peut venir de n'importe quel CMS ou générateur statique, puisque tout passe par des attributs.

Ensuite

Le principe vient d'Aristide Benoist : tout ce qui peut être calculé à la construction l'est, pour laisser à JavaScript et à WebGPU presque rien à faire à l'exécution.

  1. Fait : texte prêt pour le GPU à la construction (atlas MTSDF et SDF), gabarits et composants (ci-dessus), chaîne d'images (AVIF et WebP aux bonnes tailles, mipmaps filtrées à la construction).
  2. SVG prêts pour le GPU : convertis en champs de distance, nets à toute taille.
  3. Minification et renommage du CSS, du JavaScript et des shaders WGSL.
  4. Sortie statique ou rendu serveur (Vercel, AWS Lambda) quand le contenu vient d'un CMS.
  5. Un éditeur visuel : sélectionner un élément, régler ses attributs dans un inspecteur, exporter du HTML propre.
